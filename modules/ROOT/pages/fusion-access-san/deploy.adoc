== Introduction

This guide covers deploying IBM Fusion Access for SAN after the iSCSI infrastructure is configured. The procedure installs the IBM Storage Fusion Operator, configures Fusion Data Foundation (FDF) for local storage, and enables the External Storage Area Network (SAN) service.

Official documentation: https://www.ibm.com/docs/en/fusion-software/{fusion-version}.0?topic=fusion-access-san[IBM Fusion Access for SAN Documentation^]

NOTE: In IBM Technology Zone environments, the IBM Operator Catalog and IBM container entitlement secret are pre-configured.

== Step 1: Add IBM Operator Catalog (Reference)

The IBM Operator Catalog source is pre-configured in TechZone environments. For reference:

[source,yaml]
----
apiVersion: operators.coreos.com/v1alpha1
kind: CatalogSource
metadata:
  name: ibm-operator-catalog
  namespace: openshift-marketplace
spec:
  sourceType: grpc
  image: icr.io/cpopen/ibm-operator-catalog:latest
  displayName: IBM Operator Catalog
  publisher: IBM
  updateStrategy:
    registryPoll:
      interval: 45m
----

Verify that the catalog source is ready:

[source,shell]
----
oc get CatalogSources ibm-operator-catalog -n openshift-marketplace
----

Verify marketplace pods:

[source,shell]
----
oc get pods -n openshift-marketplace
----

== Step 2: Install IBM Fusion Operator

1. Log in to the OpenShift Web Console as `kubeadmin`.
2. Navigate to menu:Ecosystem[Software Catalog].
3. Search for `Fusion` and select the **IBM Storage Fusion** operator tile.
4. Click btn:[Install].
5. Keep the default installation settings:
   * **Update channel:** Stable channel (e.g., `v2.x`)
   * **Installation mode:** All namespaces on the cluster (default)
   * **Installed Namespace:** `ibm-spectrum-fusion-ns`
   * **Approval Strategy:** Automatic
6. Click btn:[Install].
7. Navigate to menu:Ecosystem[Installed Operators] and wait until the status shows **Succeeded**.

== Step 3: Connect to IBM Fusion Console

1. From the OpenShift Console top navigation bar, click the **Application Menu** (grid icon in masthead).
2. Click **IBM Storage Fusion**. A new browser tab opens.
3. If prompted, select **kube:admin** and enter your OpenShift cluster credentials.
4. Accept the license agreement by checking **I have read and accept the license agreement**, then click btn:[Continue].
5. You are redirected to the **Welcome to IBM Fusion** dashboard.

== Step 4: Install Fusion Data Foundation

Before configuring External SAN, install and configure Fusion Data Foundation (FDF) to provide core storage services for the cluster.

=== Install the Data Foundation Service

1. In the IBM Fusion Console, navigate to **Services** in the left navigation menu.
2. Locate the **Data Foundation** service tile and click the tile.
3. Click btn:[Install].
4. On the **Install service** screen, select the **Local** tile and click btn:[Install].
+
[NOTE]
====
Selecting **Local** automatically installs the Local Storage Operator (LSO). No separate LSO installation step is required.
====

=== Configure the Storage Cluster

1. In the Fusion Console left menu, navigate to menu:Storage[Local storage] and click btn:[Get Started].
2. Click btn:[Create Storage Cluster].
3. In the OpenShift Console storage wizard, verify that **Create a new StorageClass using local storage devices** is selected, then click btn:[Next].
4. Keep **Use Ceph RBD** as the default StorageClass, then click btn:[Next].
5. For **LocalVolumeSet name**, enter `ibm-spectrum-fusion-local`. The **StorageClass name** field is filled with the same value. Leave it as is.
6. Under **Filter disks by**, select **Disks on selected nodes**, then select only the three infra nodes (for example, `infra-1`, `infra-2`, and `infra-3`).
7. Leave **Disk type** set to **SSD / NVMe**. This is the only disk type supported for internal mode deployments.
8. Expand **Advanced** and set the following:
   * **Volume mode:** `Block` (default)
   * **Device type:** `Disk` and `Part` (default)
   * **Disk size > Minimum:** `100`, with **Units** set to `GiB`, so that only disks larger than 100 GiB are used
   * **Maximum:** leave empty
   * **Maximum disks limit:** leave as `All`
9. Click btn:[Next], select **Yes** to Create LocalVolumeSet, then click btn:[Next].
10. Accept the default capacity settings, then click btn:[Next].
11. On the **Security and network** page, accept the defaults and click btn:[Next]:
   * **Encryption:** leave **Enable data encryption for block and file storage** and **In-transit encryption** cleared
   * **Network:** leave **Default (Pod)** selected
   * **Network isolation:** leave **Isolate network using Multus** cleared
12. On the **Review and create** page, click btn:[Create Storage systems].
13. Wait for the storage cluster status to transition to **Healthy**.

=== Validate Storage Classes

From your terminal, verify the newly created storage classes:

[source,shell]
----
oc get storageclass
----

=== Configure Storage for OpenShift Image Registry

[IMPORTANT]
====
This step is only required to provide persistent storage for the OpenShift image registry.
====

Create persistent storage for the OpenShift internal container image registry using CephFS:

1. In OpenShift Console, navigate to menu:Storage[PersistentVolumeClaims].
2. Switch to the `openshift-image-registry` namespace.
3. Click btn:[Create PersistentVolumeClaim]:
   * **StorageClass:** `ocs-storagecluster-cephfs`
   * **PVC Name:** `imageregistry`
   * **Access Mode:** Shared access (RWX)
   * **Size:** `100 GiB`
4. Click btn:[Create].

Patch the OpenShift Image Registry operator to use the new PVC:

[source,shell]
----
oc patch configs.imageregistry.operator.openshift.io cluster --type merge -p '{"spec":{"managementState":"Managed","storage":{"pvc":{"claim":"imageregistry"}}}}'
----

Verify that the image registry cluster operator is healthy and available:

[source,shell]
----
oc get clusteroperator image-registry
----

== Step 5: Configure External SAN (Fusion Access for SAN)

Now configure External SAN storage utilizing the shared iSCSI LUNs prepared in the previous step.

1. In the IBM Fusion Console, navigate to menu:Data Foundation[External Systems].
2. Click btn:[Connect external Systems].
3. Select **Storage Area Network** and click btn:[Next].
4. Under **Select local cluster nodes**, keep **All Nodes (Default)** selected. All non control plane nodes are selected to handle requests to IBM Scale.
5. Under **LUN group details**, enter `{fas-fs-name}` for **Name**.
6. Under **LUNs**, select both of the shared LUNs (for example, `/dev/dm-0` and `/dev/dm-1`, 500 GiB each). Use the checkbox in the table header to select all LUNs.
7. Click btn:[Connect and create].

=== Set the VM StorageClass as the Default for Virtualization

Set `{storage-class-vm-name}` as the default StorageClass for virtualization *before* you install OpenShift Virtualization in the next guide, so that OpenShift Virtualization uses it from the start. The default virtualization StorageClass is set with the `storageclass.kubevirt.io/is-default-virt-class` annotation. It is separate from the cluster default StorageClass.

==== Option A: Set the default via the OpenShift Web Console

1. In the OpenShift Web Console, navigate to menu:Storage[StorageClasses].
2. Click `{storage-class-vm-name}`.
3. Click the **YAML** tab.
4. Under `metadata.annotations`, add the following annotation (create the `annotations` section if it does not exist):
+
[source,yaml]
----
storageclass.kubevirt.io/is-default-virt-class: "true"
----
5. Click btn:[Save].

==== Option B: Set the default via the CLI

Annotate the StorageClass:

[source,shell,subs="attributes+"]
----
oc annotate storageclass {storage-class-vm-name} storageclass.kubevirt.io/is-default-virt-class=true --overwrite
----

==== Verify the Default Virtualization StorageClass

Verify the annotation. The expected output is `true`:

[source,shell,subs="attributes+"]
----
oc get storageclass {storage-class-vm-name} -o jsonpath='{.metadata.annotations.storageclass\.kubevirt\.io/is-default-virt-class}{"\n"}'
----

[NOTE]
====
Only one StorageClass should carry this annotation. To check, run `oc get storageclass -o yaml | grep is-default-virt-class`. If another StorageClass (for example, one created by Data Foundation) has it set to `"true"`, remove it so that `{storage-class-vm-name}` is the only virtualization default.
====
