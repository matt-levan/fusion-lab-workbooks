== Introduction

This section demonstrates how to benchmark the IBM Fusion Access for SAN storage class using KubeStr.

For comprehensive storage benchmarking on Red Hat OpenShift with FIO, refer to:
https://community.ibm.com/community/user/viewdocument/benchmarking-your-storage-on-redha?CommunityKey=e596ba82-cd57-4fae-8042-163e59279ff3&tab=librarydocuments[Benchmarking Your Storage on Red Hat OpenShift with FIO (IBM Community Guide)^]

== Tool: KubeStr

KubeStr is a Kubernetes storage benchmarking tool that discovers CSI drivers and executes synthetic FIO workloads against storage classes.

Download: https://github.com/kastenhq/kubestr/releases/latest[KubeStr Releases^]

== Step 1: Discover CSI Drivers and StorageClasses

Run KubeStr to discover available CSI storage classes:

[source,shell]
----
./kubestr fio
----

Expected output: KubeStr identifies the `{storage-class-name}` StorageClass and associates it with the `spectrumscale.csi.ibm.com` CSI driver.

== Step 2: Run Benchmark Against Fusion Access for SAN

Run KubeStr against the `{storage-class-name}` StorageClass:

[source,shell,subs="attributes+"]
----
./kubestr fio --storage-class {storage-class-name}
----

== Important Considerations

[NOTE]
====
The lab environment is designed for architectural demonstration and functionality validation:
* Single-node IBM Storage Scale target
* Nested virtualization
* Single network interface

Benchmark metrics gathered in this lab environment reflect test-bed constraints and should not be used as representative sizing metrics for production bare-metal environments.
====

== Production Benchmarking Best Practices

For production validation:

* **Bare-metal worker nodes** with dedicated dual-port SAN/iSCSI adapters
* **Multiple Storage Scale cluster nodes** for high availability and load balancing
* **Multipath I/O** active across redundant network paths
* **Representative workload profiles** matching production I/O size and queue depths
* **Extended test duration** to reach steady-state performance
