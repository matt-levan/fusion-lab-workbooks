== Introduction

This section covers configuring iSCSI on OpenShift worker nodes using Linux-IO (LIO) as the iSCSI target, with IBM Storage Scale as the backing store.

=== About iSCSI

IBM and Cisco Systems jointly developed the iSCSI protocol in 1998. It was submitted as a draft standard in 2000 and officially published as RFC 3720 by the IETF in 2004.

iSCSI encapsulates SCSI commands and data into TCP/IP packets for transmission over a standard network. It is widely used due to its cost-effectiveness and simplicity compared to alternatives like Fibre Channel.

The three core components of iSCSI:

* **iSCSI initiator:** Client-side software or hardware that connects to storage (OpenShift worker nodes).
* **iSCSI target:** Storage server that receives connections and serves storage (IBM Storage Scale node).
* **iSCSI Qualified Name (IQN):** Unique identifier used to address iSCSI initiators and targets.

=== Why iSCSI for OpenShift?

Deploying worker nodes with dedicated Fibre Channel host bus adapters (HBAs) connected to SAN-attached storage can be costly. iSCSI is an efficient and cost-effective alternative running over standard Ethernet. We use the Linux-IO (LIO) target subsystem built into the Linux kernel.

=== Example Scripts and Manifests

The configuration manifests and helper scripts are available in the repository examples directory:

* `examples/yaml/iscsi-mco.yaml` — MachineConfig for multipath configuration and iSCSI service enablement

== Step 1: Prepare the Scale Node

Log in to the IBM Storage Scale node as described in xref:getting-started/access.adoc#_ssh_to_ibm_storage_scale_node[Accessing Your TechZone Lab Environment].

=== Install Required Packages

Install `targetcli` and `iscsi-initiator-utils`:

[source,shell]
----
dnf install -y targetcli iscsi-initiator-utils
----

=== Configure Firewall

Verify if `firewalld` is active:

[source,shell]
----
firewall-cmd --state
----

If the firewall is running, permanently open port `{iscsi-target-port}` (3260/tcp) for iSCSI traffic and reload rules:

[source,shell,subs="attributes+"]
----
firewall-cmd --permanent --add-port={iscsi-target-port}/tcp
----

Reload firewall configuration:

[source,shell]
----
firewall-cmd --reload
----

Verify open ports:

[source,shell]
----
firewall-cmd --list-ports
----

Expected output showing open ports:

[source,text,subs="attributes+"]
----
1191/tcp {iscsi-target-port}/tcp 60000-61000/tcp
----

=== Verify Filesystem Mount

Verify that the Scale filesystem is mounted and has sufficient capacity:

[source,shell,subs="attributes+"]
----
df -h {scale-fs-mount}
----

This filesystem (`{scale-fs-name}`) serves as the backing store for the iSCSI LUNs.

== Step 2: Configure Worker Nodes via MachineConfig

Before connecting to the iSCSI target, apply the MachineConfig to configure `/etc/multipath.conf` and enable the `iscsid.service`, `iscsi.service`, and `multipathd.service` systemd units on all worker nodes.

The embedded `/etc/multipath.conf` sets `find_multipaths no` so that multipath maps are created for every iSCSI LUN, including LUNs with a single path, and blacklists the local OS disks (`vda`, `sr`, `loop`). With the default `find_multipaths yes`, `multipath -ll` returns no devices for single-path LUNs.

From your workstation or Bastion CLI with `oc` authenticated:

Apply the MachineConfig manifest:

[source,shell]

----

Monitor the worker MachineConfigPool rollout:

== Step 3: Configure iSCSI Target on Scale Node using `targetcli`

`targetcli` provides an interactive shell with a tree-like hierarchy to manage the Linux-IO target subsystem.

=== Configuration Workflow

1. Create file-backed storage objects in `backstores/fileio`
2. Create the target IQN in `iscsi/`
3. Map LUNs in `tpg1/luns`
4. Configure target access permissions
5. Save configuration and verify listener

=== Launch targetcli

On the Scale node shell as `root`, start `targetcli`:

[source,shell]
----
targetcli
----

=== Create Backing Store Files

Create two {lun-size} file-backed storage objects on the Scale filesystem:

[source,shell,subs="attributes+"]
----
/backstores/fileio create iscsilun0 {scale-fs-mount}/iscsilun0 {lun-size}
----

Create the second LUN file:

[source,shell,subs="attributes+"]
----
/backstores/fileio create iscsilun1 {scale-fs-mount}/iscsilun1 {lun-size}
----

Verify the backstores:

[source,shell]
----
/backstores/fileio ls
----

=== Create iSCSI Target IQN

Create the target IQN (this automatically creates default Target Portal Group `tpg1`):

[source,shell,subs="attributes+"]
----
/iscsi create {iscsi-target-iqn}
----

=== Configure Target Portal Group (TPG) Attributes

Configure the target portal group for open access with dynamic node ACLs. This is intended for lab simplicity only.

Disable CHAP authentication. Because authentication is disabled, the worker nodes can log in without credentials:

[source,shell,subs="attributes+"]
----
/iscsi/{iscsi-target-iqn}/tpg1 set attribute authentication=0
----

Enable dynamic node ACL generation so that any initiator IQN (the worker nodes) is granted access to the LUNs without creating explicit ACLs:

[source,shell,subs="attributes+"]
----
/iscsi/{iscsi-target-iqn}/tpg1 set attribute generate_node_acls=1
----

Disable demo mode write protection so the worker nodes can write to the LUNs:

[source,shell,subs="attributes+"]
----
/iscsi/{iscsi-target-iqn}/tpg1 set attribute demo_mode_write_protect=0
----

Enable dynamic ACL caching so that the generated node ACLs persist across target service restarts:

[source,shell,subs="attributes+"]
----
/iscsi/{iscsi-target-iqn}/tpg1 set attribute cache_dynamic_acls=1
----

=== Map Backstores to LUNs

Map `iscsilun0` to LUN 0:

[source,shell,subs="attributes+"]
----
/iscsi/{iscsi-target-iqn}/tpg1/luns create /backstores/fileio/iscsilun0
----

Map `iscsilun1` to LUN 1:

[source,shell,subs="attributes+"]
----
/iscsi/{iscsi-target-iqn}/tpg1/luns create /backstores/fileio/iscsilun1
----

Verify mapped LUNs:

[source,shell,subs="attributes+"]
----
/iscsi/{iscsi-target-iqn}/tpg1/luns ls
----

=== Save and Exit targetcli

Save the target configuration to disk:

[source,shell]
----
saveconfig
----

Exit `targetcli`:

[source,shell]
----
exit
----

=== Set File Permissions

Ensure proper permissions on the backing store files:

[source,shell,subs="attributes+"]
----
chmod 777 {scale-fs-mount}/iscsilun*
----

=== Verify Target Listener

Verify that the iSCSI daemon is listening on port `{iscsi-target-port}`:

[source,shell,subs="attributes+"]
----
ss -tlpn | grep {iscsi-target-port}
----

Expected output:

[source,text,subs="attributes+"]
----
LISTEN 0      256          0.0.0.0:{iscsi-target-port}        0.0.0.0:*    users:(("iscsi_trx",pid=...,fd=...))
----

== Step 4: Discover and Connect iSCSI LUNs from OpenShift Nodes

With the target active and the MachineConfig deployed, discover and log into the target from the OpenShift nodes using `oc debug`.

=== Discover iSCSI Target from Worker Nodes

Run target discovery on all worker nodes:

[source,shell,subs="attributes+"]
----
for NODE in $(oc get nodes -l node-role.kubernetes.io/worker -o jsonpath='{.items[*].metadata.name}'); do echo "=== Discovering on $NODE ==="; oc debug node/$NODE -- chroot /host iscsiadm -m discovery -t sendtargets -p {scale-node-ip} 2>/dev/null; done
----

Expected output for each node:

[source,text,subs="attributes+"]
----
{scale-node-ip}:{iscsi-target-port},1 {iscsi-target-iqn}
----

=== Log In to the iSCSI Target

Establish the iSCSI session on all worker nodes:

[source,shell,subs="attributes+"]
----
for NODE in $(oc get nodes -l node-role.kubernetes.io/worker -o jsonpath='{.items[*].metadata.name}'); do echo "=== Logging in on $NODE ==="; oc debug node/$NODE -- chroot /host iscsiadm -m node -T {iscsi-target-iqn} -p {scale-node-ip} -l 2>/dev/null; done
----

=== Verify Block Devices on OpenShift Nodes

Check that the new shared SCSI block devices (`sda`, `sdb` or similar) are visible on each node:

[source,shell]
----
for NODE in $(oc get nodes -l node-role.kubernetes.io/worker -o jsonpath='{.items[*].metadata.name}'); do echo "=== Devices on $NODE ==="; oc debug node/$NODE -- chroot /host lsblk 2>/dev/null; done
----

=== Verify Multipath Status

Check multipath mapping on the worker nodes:

[source,shell]
----
for NODE in $(oc get nodes -l node-role.kubernetes.io/worker -o jsonpath='{.items[*].metadata.name}'); do echo "=== Multipath on $NODE ==="; oc debug node/$NODE -- chroot /host multipath -ll 2>/dev/null; done
----

Expected output showing multipath device maps for both LUNs:

[source,text]
----
360014050d784c01f99d40cab46abc818 dm-1 LIO-ORG,iscsilun0
size=100G features='0' hwhandler='1 alua' wp=rw
`-+- policy='service-time 0' prio=50 status=active
  `- 7:0:0:0 sda 8:0  active ready running
3600140524b1c32da8b04c8abf57d5d34 dm-0 LIO-ORG,iscsilun1
size=100G features='0' hwhandler='1 alua' wp=rw
`-+- policy='service-time 0' prio=50 status=active
  `- 7:0:0:1 sdb 8:16 active ready running
----

== Step 5: Validate Node Drain and Recovery

Validate that iSCSI connections and device mappings persist across node maintenance and reboots.

Cordon a worker node:

[source,shell]
----
oc adm cordon itz-ria1e6-worker-1
----

Drain workloads from the node:

[source,shell]
----
oc adm drain itz-ria1e6-worker-1 --ignore-daemonsets --delete-emptydir-data --force
----

Uncordon the node once maintenance verification is complete:

[source,shell]
----
oc adm uncordon itz-ria1e6-worker-1
----

Verify that the iSCSI block devices remain attached and available:

[source,shell]
----
oc debug node/itz-ria1e6-worker-1 -- chroot /host multipath -ll 2>/dev/null
----
